## 1. Что это

**ACAI** — внутренний веб-сайт кирпичного завода **Astana Ceramic**
(Казахстан, Астана). Работает в локальной сети завода на одном Mac.
Пользователи — рабочие цехов (с телефонов), механики, электрики,
мастера смен, главный инженер, технолог, лаборанты, директор.

Главное назначение:
- **Обращения о поломках**: рабочий описывает проблему, ИИ ведёт по шагам,
  если не помогло — подключается механик или электрик, закрытие подтверждает
  человек.
- Учёт оборудования, простоев, планового ТО, обходов смены, выпуска
  продукции, сменных отчётов упаковки.
- Регламенты и технологические нормы, лабораторный журнал.
- Показания датчиков линии массоподготовки с панели WebHMI.
- Переписка между сотрудниками (личные сообщения, группы, файлы, голосовые).
- Аналитика и отчёты для руководства.

Весь интерфейс, комментарии в коде и коммиты — **на русском**. Пользователь
(владелец, логин `alibek`, роль admin) пишет по-русски, коротко и часто
без знаков препинания. Отвечай ему по-русски, простыми словами.

## 2. Стек и запуск

- **Backend**: Python 3.13, FastAPI, uvicorn. Без Docker.
- **Frontend**: Jinja2-шаблоны + чистый JS/CSS, **без сборки** (нет npm,
  React и бандлера). Шрифты локальные (`frontend/static/fonts/`), от
  интернета сайт не зависит.
- **Базы**: SQLite.
  - `factory.db` — всё основное, работа через **сырой `sqlite3`**
    (`backend/config.py: DB_NAME`).
  - `monitoring.db` — только показания датчиков (`sensor_readings`),
    через SQLAlchemy (`backend/database.py`, `backend/models.py`).
    Остальные модели SQLAlchemy — остатки, не используются.
- **ИИ**: OpenAI (`backend/services/ai_service.py`, ключ `OPENAI_API_KEY`
  в `.env`). Поиск по документации — ChromaDB (`knowledge_base/`),
  эмбеддинги `paraphrase-multilingual-MiniLM-L12-v2`.
- `.env` читается самим `backend/config.py` (launchd не передаёт
  переменные окружения). **Не выводи содержимое `.env` и не коммить его.**

### Как крутится в проде (launchd, пользовательские агенты)

| агент | что | где плист |
|---|---|---|
| `com.acai.server` | uvicorn `0.0.0.0:8000`, http | `~/Library/LaunchAgents/`, копия в `deploy/` |
| `com.acai.server.https` | тот же код на `0.0.0.0:8443`, https, сертификат из `certs/`, подписанный заводским корневым (нужен для микрофона и уведомлений на телефонах) | то же |
| `com.acai.backup` | `scripts/backup/backup_full.py` каждый день в 02:00 | то же |
| `com.acai.backup.docs` | то же с `--with-docs`, по воскресеньям в 03:00 | то же |

- Флага `--reload` нет. **После правки Python-кода перезапускай оба
  сервера**:
  ```bash
  launchctl kickstart -k gui/$(id -u)/com.acai.server
  launchctl kickstart -k gui/$(id -u)/com.acai.server.https
  ```
- Правки HTML/JS/CSS перезапуска не требуют, но в шаблонах у подключений
  стоит `?v=N`. **Меняешь статический файл — увеличь `v` во всех
  шаблонах, где он подключён**, иначе телефоны покажут старую версию из кэша.
- Логи: `logs/server.log`, `logs/server.error.log`, `logs/server_https*.log`,
  `logs/backup*.log`. Ротацию делает ночной бэкап.
- IP сервера в локальной сети: `192.168.0.184` (прописан в сертификате).
  Панель WebHMI: `192.168.1.74`.
- Python из venv: `./venv/bin/python`. pytest не установлен: тесты
  запускаются как скрипты (`./venv/bin/python tests/test_page_roles.py`).
  Playwright и Pillow в venv есть.

## 4. Пользователи, роли, доступ

Вход по сессионной cookie `session_token` (таблица `sessions`, срок 12 ч).
Сервис — `backend/services/auth_service.py`, пароли PBKDF2. JWT в проекте
нет (старую JWT-ветку удалили).

Роли (`VALID_ROLES`): `admin`, `director`, `chief_engineer`, `engineer`,
`shift_supervisor` (мастер смены), `worker`, `technologist`,
`lab_technician`, `chief_mechanic`, `mechanic`, `chief_electrician`,
`electrician`, `analyst`.

- `admin` проходит все проверки. Владельцы — `OWNERS` в `.env`
  (`is_owner()`); им доступны бэкапы, восстановление и подтверждение
  опасных удалений.
- Рабочие привязаны к станкам (`worker_equipment`) и видят только свои.
  Логины бригад: `a-massa-1`, `b-kiln-2`, `a-pack-1` и т. п. (бригады А/Б/В/Г,
  участки массоподготовка/печь/упаковка).
- Отключённый сотрудник: `users.is_active = 0`, войти не может, история
  сохраняется. Скрытая техническая учётка: `users.hidden = 1`.

**Порядок `app.include_router` в main.py важен**: при совпадении адреса
отвечает маршрут, подключённый раньше. Новый маршрут клади в файл своего
раздела, а не в main.py.

**Доступ к страницам проверяется дважды, и списки должны совпадать:**
1. `PAGE_ROLES` в `backend/api/main.py` — middleware `page_access_guard`
   отдаёт `no_access.html`;
2. `NAV_ITEMS` в `frontend/static/acai_layout.js` — пункты меню.

Совпадение проверяет `tests/test_page_roles.py`. **Меняешь роли у
страницы — меняй в обоих местах и запусти тест.** Права API проверяются в
каждом обработчике отдельно (`require_roles(...)`, свои проверки в
роутерах). Скрытая кнопка — не защита.

Куда ведёт вход: `ROLE_HOME_PAGE` в `main.py` = `ROLE_HOME_PAGE` в
`static/login.js` (рабочий → `/chat`, механики → `/mechanics`, электрики →
`/electrical`, технолог и лаборант → `/lab`, мастер и инженер →
`/production`, остальные → `/`).

## 6. Ключевые подсистемы

### 6.1 Обращения (`/chat`)
- Файлы: `conversation_service.py`, `conversation_routes.py`,
  `response_service.py`, `case_service.py`, `static/chat.js`, `chat.css`.
- Создание: `POST /diagnose` (в `main.py`) создаёт `cases`, автоматически
  начинает простой (`downtime_service`) и выдаёт первый шаг.
- Статусы: `Открыто` → `Требует специалиста` → `В работе` →
  `Черновик закрытия` → `Закрыто`.
- Откуда берутся ответы (по приоритету, `response_service.build_answer` и
  `conversation_service.generate_reply`):
  0. код ошибки PLC из текста (`plc_error_service.find_by_code`); решение
     делится на шаги `split_solution_steps` и отдаётся **по одному шагу**;
  1. инструкция завода (`procedures_service`) — по шагу;
  2. легаси-сценарии (`instruction_service`, сейчас только «плёнка»);
  3. ИИ с документацией из Chroma и подтверждёнными решениями
     (`knowledge_service`).
  Не больше `MAX_AI_STEPS` (3) шагов, затем передача специалисту;
  дисциплину (механика/электрика) определяет ИИ.
- **Честное «не знаю»** (с 17.09.2026): в совет ИИ идёт только руководство
  ЭТОГО станка (`vector_service.own_machine_documents`; сам
  `search_documents` без своей папки ищет по всем — раньше ИИ отвечал по
  чужим паспортам со «Средней уверенностью»). Нет своих фрагментов и нет
  подтверждённых решений → ИИ не советует, а сразу пишет «по станку «X» у
  меня нет руководства / в руководстве не нашёл — гадать не буду» и
  передаёт специалисту (`response_service.honest_unknown`,
  `conversation_service.escalate_unknown`). Жалоба и причина остаются в
  переписке.
- Сопоставление станок → папка документации нестрогое (`resolve_docs_folders`);
  где не угадывается — `DOCS_FOLDER_OVERRIDES`. Руководство есть у 36 из 49
  станков (верхняя оценка). Упаковочная машина → «упаковка на линию мessersi»,
  но её паспорт — таблицы электросхем, фильтр отсекает всё: ответы по ней
  появятся только из закрытых обращений или текстового руководства.
- У рабочего под шагом ИИ быстрые кнопки **«Помогло / Не помогло /
  Позвать мастера»** (`/resolve`, сообщение «Не помогло», `/escalate`), на
  форме нового обращения — быстрые варианты проблем. Если рабочий пишет
  «заработало», ИИ **не закрывает сам**, а спрашивает «Станок работает?»:
  закрывает человек.
- Закрытие через главного инженера пополняет базу знаний.
- Страница «Обращения» по умолчанию светлая (`data-default-theme="light"`),
  тёмная — по кнопке.

### 6.2 Переписка (`/messenger`)
- `team_chat_service.py`, `team_chat_routes.py` (`/api/messenger/...`),
  `static/messenger.js/css`.
- Таблицы: `team_conversations` (dm/group), `team_members`
  (`last_read_message_id`, `cleared_before_id`), `team_messages`
  (удаление мягкое — «сообщение удалено»), `team_attachments`.
- Вложения до 50 МБ, пишутся потоком в `uploads/messenger/ГГГГ-ММ/`.
  Картинкам делается превью с удалённым EXIF. Встроенно показываются
  только image/video/audio, остальное отдаётся на скачивание. Файл
  удалённого сообщения стирается с диска.
- История подгружается порциями (`before_id`), новые сообщения — опросом (`after_id`).
- Как в WhatsApp: «Удалить чат» в личке скрывает историю только у себя
  (новое сообщение возвращает чат), «Выйти из группы», «Удалить группу
  для всех» (создатель или admin). Меню ⋮ в шапке.
- Голосовые — обычное вложение `audio/*`.

### 6.3 Диктофон (`static/voice.js`, `api/voice_routes.py`)
- `ACAIVoice.recordButton` — голосовое сообщение (Переписка);
  `ACAIVoice.dictateButton` — голос в текст в поле (Обращения, Диагностика).
  Запись включается и выключается нажатием, держать кнопку не нужно.
- `POST /api/voice/transcribe` → OpenAI (`gpt-4o-mini-transcribe`,
  запасная `whisper-1`, `language=ru`, подсказка с терминами завода). Звук не
  хранится.
- **Микрофон в браузере работает только на https или localhost.** С
  `http://192.168…:8000` кнопка предлагает перейти на
  `https://192.168.0.184:8443`. Без установленного заводского сертификата
  (`/cert`) телефон покажет предупреждение.

### 6.4 Датчики WebHMI
- Расширение Chrome `tools/webhmi-extension/` (установленная копия —
  `~/Downloads/webhmi-extension`, в ней вписан настоящий ключ) работает
  во вкладке панели `http://192.168.1.74/lp` и раз в секунду шлёт показания
  на `http://localhost:8000/api/sensors/live` (в память сервера).
- **В базу пишет сервер** (`services/sensor_recorder.py`): загрузки,
  авария и моточасы — раз в 30 с, частоты (Гц) — раз в 7 мин и при
  изменении. Пишет только пока живые данные свежие (≤ 90 с).
- Панель присылает только изменившиеся регистры, поэтому расширение v5
  помнит последние значения. Таймер в Web Worker — против притормаживания
  фоновой вкладки.
- Экземпляр на 8443 живых данных не получает и берёт их у 8000

## 7. Интерфейс: правила

**Принципы (от владельца, 17.09.2026):**
- **Цвет = отклонение.** Норма серая, красный/жёлтый — только где нужно
  вмешаться. `.metric.ok`, `.badge.ok`, `.dot-status.ok` в `acai.css`
  нарочно нейтральные. Не крась «Работает», «Закрыто», «Норма».
- **Экран отвечает на один вопрос.** Главная: сверху `#verdict` —
  «Завод работает» или 2–3 строки «требует решения» (из
  `/api/notifications`, critical+warning); цифры, цепочка, календарь ниже.
- **Лесенка: сводка → список → запись.** Каждое оповещение несёт `url`
  на конкретную запись; `bellLink` в `acai_layout.js` берёт его.
  Обращение открывается по `/chat?case=N`. Не веди с главной в общий
  список на сорок строк.
- **Аналитика: сначала выводы** (`#conclusions`, `renderConclusions`),
  потом графики. «Данных нет» вместо нулей (раздел 6.7).
- **Обращения: «чей ход» одной плашкой** (`#chatTurn`, `turnOf` в
  `chat.js`): «Ждём механика», «Слесарь Петров ответил», «Ваш ход: …».
  Цвет — только «ваш ход»; непрочитанное — точка и жирный шрифт
  (последний виденный `chat_history.id` в `localStorage`).
- **Солнце в цеху.** Второстепенный текст — контраст ≥ 7 к фону
  (`--text-dim`: тёмная `#9aa6b8`, светлая `#414b5a`), на телефоне не
  мельче 12px. Проверяй контраст расчётом, не на глаз с экрана мака.

- **Тема**: `theme.js` в `<head>` каждой страницы ставит
  `html[data-theme="light|dark"]` из `localStorage.acai_theme`. Цвета —
  только через переменные `acai.css` (`--bg`, `--surface`, `--surface-2`,
  `--border`, `--text`, `--text-dim`, `--ok`, `--warn`, `--danger`,
  `--accent`, `--shadow`, `--backdrop`). **Не пиши жёсткие цвета фона и
  текста** — сломается одна из тем. Для `/chat` тёмная палитра задана
  отдельным блоком в конце `chat.css`. Кнопка темы — в шапке рядом с
  колокольчиком и в карточке пользователя в меню.
- Новая страница: `theme.js` → `fonts.css` → `acai.css` в `<head>`;
  в конце `acai_layout.js` и `mobile_nav_v2.js`; разметка `.sidebar` +
  `.topbar` + `.page`; добавить в `PAGE_ROLES` и `NAV_ITEMS`. У пунктов
  меню уникальные эмодзи.
- Телефон — главный клиент в цеху: проверяй ширину 390 px, крупные
  кнопки, без горизонтальной прокрутки.
- Помощники `ACAI.get/post`, `ACAI.toast`, `ACAI.showModal/closeModal`,
  `ACAI.localDate()/localDateTime()` — в `acai_layout.js`.

## 8. Грабли (уже наступали)

1. **Время.** Завод в UTC+5. SQLite `datetime('now')` — это UTC: используй
   `datetime('now','localtime')`, в Python — `datetime.now()`. В браузере
   `toISOString()` тоже UTC: бери `ACAI.localDate()` / `localDateTime()`.
   Из-за этого однажды всё показывало на 5 часов меньше.
2. **Сессии.** В тестах создавай свою сессию прямой вставкой в `sessions`
   и **удаляй только её по токену**. Никогда не выполняй
   `DELETE FROM sessions WHERE ...` по условию: так уже разлогинили
   живых пользователей, и владелец неделю жаловался, что его «выкидывает».
3. **Тестовые данные.** Сквозные проверки создают реальные записи:
   обращение, простой, запись в журнале, смену статуса станка. Перед
   тестом запомни `MAX(id)` таблиц и строку станка, после — удали своё и
   восстанови станок. Не удаляй то, что создал не ты. Перед рискованными
   действиями делай копию базы (`sqlite3 factory.db ".backup ..."`).
4. **Два экземпляра сервера** (8000 и 8443) делят базы, но не память:
   кэш живых датчиков, счётчики rate-limit. Фоновые потоки, которые пишут
   в базу, должны работать только в одном экземпляре.
5. **Кэш статики** — поднимай `?v=`.
5а. **Пути к файлам** бери из `backend/config.py` (`DOCS_PATH`,
    `MESSENGER_FILES_DIR`, `CHECKLIST_PHOTOS_DIR`, `BACKUPS_DIR`,
    `STATIC_UPLOADS_DIR`, `CHROMA_DB_PATH`), а не `BASE_DIR / "..."` и не
    абсолютные пути: иначе песочница проверок будет писать в живые папки.
5б. **Дубли маршрутов.** Один адрес в двух файлах — второй молча не
    работает (так были мёртвы загрузка и список документов станка в
    `equipment_routes.py`, а настоящие — в `regulation_routes.py`). Ловит
    `tests/test_routes_unique.py`.
5в. В тестах `../` в адресе клиент схлопывает сам — выход из папки проверяй
    закодированным `%2e%2e/` и жди именно 403.
6. **Не тот ответ от API у рабочего**: рабочий видит только свои станки
   (`get_assigned_equipment_ids`), проверки в `/diagnose` и `_check_access`.
7. `messenger.js` обёрнут в IIFE — код, добавленный после `})();`, не
   видит переменных страницы. Функции для `onclick` экспортируются через
   `window.*` в конце файла.
8. `equipment.health` никто не обновляет — исправность считается в
   `equipment_health_routes.py`.
9. Заводская сеть медленная, Mac с 8 ГБ памяти уходит в своп: таймауты
   Playwright бывают из-за этого, а не из-за страницы.
10. **Учёт использования и тесты.** Любой заход под учёткой сотрудника
    пишется в `usage_daily`. 17.09 проверки по всем ролям накрутили заходы
    13 сотрудникам (12:32–13:04). Сохраняй строки пользователя до теста и
    возвращай после.
11. Статус станка после теста: «Дробилка DTE 117» (id 281) однажды
    осталась в «Внимание» после теста — проверяй статусы после e2e.

    обращение / переписка, управление людьми и бэкапами, уволенный,

  - `tests/test_restore.py` — учение по восстановлению из ночной копии.

## 11. Что сделано (сентябрь 2026, после «ACAI v2»)

Подробности — в `git log` (сообщения коммитов по-русски, с причинами).
Здесь — карта, чтобы не делать второй раз и понимать, откуда что.

**Доступ и безопасность**
- Страницы закрыты по должностям на сервере (`PAGE_ROLES`), а не только
  спрятаны в меню; тест сверяет с меню.
- Увольнение = отключение учётки (`is_active=0`), сессии гаснут сразу.
- Ключ приёма показаний датчиков; пароль WebHMI вынесен в `.env`;
  файл доступов убран из репозитория.
- Директор/гл. инженер больше не могут сбросить пароль владельца или
  завести администратора (было возможно через `/api/admin/users`).
- Фото и обходы смены закрыты по ролям; скачивание документов — проверка
  `is_relative_to` (старая `startswith` пропускала соседнюю папку `docs_*`).
- Ответ 422 не возвращает присланное (пароль из неудачного входа).

**Обращения и ИИ**
- ИИ честно говорит «нет руководства — зову специалиста» вместо общих
  советов по чужой документации; аналитика пишет «данных нет» вместо нулей.
- Быстрые кнопки проблем; «Помогло / Не помогло / Позвать мастера»;
  решение по коду PLC отдаётся по шагу; 281 решение к кодам PLC.
- Шаги ИИ берут код ошибки из последней жалобы (новая жалоба дописывается
  в открытое обращение по станку).
- Подтверждение закрытия без правок больше не стирает текст ремонта —
  решение попадает в базу знаний.

**Оформление**
