## Три изъяна, которые нашлись при чтении базы

**1. Каждая загрузка стирает предыдущую.** В коде
`DELETE FROM xls_* WHERE year = ?`. В журнале одиннадцать загрузок, а
данные есть только от последней (`run_id = 11`). Откатиться к прошлой
версии нельзя, сравнить «что изменилось между 24.09 и 28.09» — нельзя.
Залил испорченный файл — прежние данные исчезли без возврата.

**2. Дубль 30.06 живёт в базе.** Строк смен 538, различных пар
«дата + смена» — 537. Это та самая ночь, записанная и из «Июня», и из
«Июля». Сейчас она молча удваивает июньские суммы.

**3. «Не разобрано» негде посмотреть.** 51 простой из 416 лежит с
пустыми минутами. Число видно, строки — нет: какие именно интервалы не
прочитались, человек узнать не может.

## Схема

### Слой 1. Прогоны вместо затирания

`xls_imports` дополняется (через `ALTER TABLE`, старые записи целы):

| Поле | Зачем |
|---|---|
| `status` | `active` — то, что показывают экраны; `replaced` — прошлые; `failed` — разбор не дошёл до конца |
| `checksum` | тот же файл залили дважды — видно сразу, не надо сверять глазами |
| `rows_total`, `rows_unparsed` | сколько строк прочиталось и сколько нет |
| `note` | чем эта загрузка отличается, словами |

Правило: **ничего не удаляем.** Новая загрузка — новый `run_id`,
прошлый получает `replaced`. Экраны читают только `active`. Откат —
переключение `active` на прошлый прогон, без повторного разбора файла.
Старые прогоны чистятся только по слову владельца, автоматической
чистки нет.

Прогон `11` остаётся как есть и помечается `active`: переразбирать
ничего не нужно, данные на экранах не мигнут.

### Слой 2. Новые поля — узкой таблицей, а не колонками

Из карты колонок: в системе 9 полей из 30. Не переносятся печь, уголь,
бункеры, сушилка, запас на линии, штабели, задание на смену и весь
месячный итог. По 14 из них смысл неизвестен — вопросы начальнику
производства открыты.

Поэтому новые данные ложатся в **одну узкую таблицу**, а не в
колонки `xls_shifts`:

```
xls_values(run_id, year, date, shift, key, title,
           value_num, value_text, unit, sheet, row)
```

| | Колонки в `xls_shifts` | Узкая таблица |
|---|---|---|
| Сохранить то, чего не понимаешь | нужно придумать имя и тип | кладётся как есть, с заголовком из файла |
| Ответ начальника пришёл | миграция базы | правка справочника |
| Колонка появилась с июля | `ALTER TABLE` | ничего |
| Неверное толкование | уже записано в имя колонки | видно, что это сырое значение |

Это прямо следует из двух твоих правил: «ничего не отбрасывай молча» и
«привязать неверно хуже, чем не привязать». Сейчас сохраняем **всё**,
называем — когда придут ответы.

В `xls_shifts` отдельными колонками уходит только то, что уже понятно
без вопросов: `kiln_speed`, `carts_fact`, `master_note`. Остальное —
в узкую таблицу.

### Слой 3. Итоги месяца и непрочитанное

```
xls_month_totals(run_id, year, month, key, title, value_num, value_text, sheet, row)
xls_unparsed(run_id, year, sheet, row, column, header, raw, reason)
```

Первая — строки 65–71 листа: «выполнение плана», «остаток до плана»,
хвост со стрейч-плёнкой и остатками. Вторая — всё, что не
прочиталось: не число, не дата, `#NUM!`, пустой интервал. Она и есть
ответ на «не разобрано N записей»: список со ссылкой на лист и строку,
а не голое число.

### Слой 4. Дубли и расхождения — помечаются, не схлопываются

В `xls_shifts` добавляются `dup_of` и `conflict`:

- 30.06 из «Июля» получает `dup_of` на строку из «Июня» и в суммы не
  идёт, но из базы не исчезает;
- расхождение колонок A и B (строки 33, 44, 51 на всех листах)
  пишется в `conflict` — видно начальнику производства, в суммы не
  вмешивается.

Молча схлопнуть — значит соврать в сумме и не дать это заметить.

## Перенос: по шагам, без удаления

1. Новые таблицы создаются рядом, `CREATE TABLE IF NOT EXISTS`.
   Существующие шесть не трогаются.
2. Новые поля — `ALTER TABLE ADD COLUMN`, как уже делалось с
   `defect_pieces`. Старые строки получают `NULL`, а не значение по
   умолчанию: «не знаем» и «ноль» — разные вещи.
3. Прогон `11` помечается `active`, остальные десять — `replaced`.
   Данных у них нет, но журнал остаётся.
4. Копия базы снимается до миграции, как обычно.
5. Первая загрузка по новой схеме пишет новый прогон. Если разбор
   окажется хуже прежнего, `active` возвращается на `11` одной
   строкой.

Откат всей затеи: новые таблицы пустые, новые колонки `NULL` — старый
код читает базу как читал.

## Когда в Экселе появляется новое

Файл ведут люди. Однажды вставят графу, впишут новый вид изделия или
поставят метку, которой раньше не было. Два случая описаны отдельно,
потому что ведут себя по-разному.

### Новый заголовок колонки

Колонка, которую разбор не узнал — ни простой, ни план, ни выпуск, ни
брак:

1. значение ложится в `xls_values` **как есть**: заголовок из файла,
   лист, строка, единица, если она в подзаголовке;
2. `key = "new"` — пометка «новое, смысл не определён». Своё имя
   колонка получит, когда начальник производства скажет, что это;
3. лист попадает в список на привязку одной строкой: «новая графа
   „Стреч плёнка мессерси": 47 значений сохранены, смысл не определён
   — нужна привязка». Одной строкой на лист, а не на каждую строку:
   человеку нужен список граф, а не пятьсот повторов.

Тихо пропасть колонка не может: её либо узнали, либо она в списке.

### Новое значение в знакомой колонке

Шестой вид изделия там, где было пять; смена с меткой, которой
разбор не знает.

1. значение сохраняется наравне с остальными — новый вид кирпича
   попадает в выпуск как вид, а не как «прочее»;
2. **сумма разобранного сверяется с итоговой строкой листа**
   («Средние значения» — на деле суммы по колонкам). Разошлось —
   расхождение называется вслух, с колонкой и числами;
3. строка с данными и неразобранной меткой — отдельная запись: «строка
   с данными, но метку „№53," не разобрал».

Складывается именно **разобранное**, а не колонка из файла: потеря
происходит при разборе, и сверка «файл с файлом» сошлась бы всегда.
Допуск — десятая процента: ловить округление дробей незачем.

Эта сверка уже нашла четыре молча терявшиеся смены — строку 21 с
меткой «№53,» в июне, июле, августе и сентябре.

## Брак: что в файле есть и чего нет

| Месяц | Колонок «Брак и отстрел» | Заполнено |
|---|---|---|
| Январь — май | нет вовсе | — |
| Июнь | одна | пусто |
| Июль, август | одна, «штук» | 28 и 32 смены |
| Сентябрь | пять, две подписаны видом | 42 смены |

Разбивки **по участкам** (формовка, обжиг, упаковка) в файле нет ни в
одном месяце. Разделения **брака и отстрела** нет тоже: это одна
колонка с одним числом, названная «Брак и отстрел».

Что есть с сентября — разбивка **по видам изделия**: своя колонка
брака перед каждым видом. Три из пяти подписаны просто «Брак и
отстрел», к какому виду относятся — файл не говорит.

До 30.09.2026 разбор брал первую колонку и показывал 8 164 штуки из
17 016. Теперь складываются все, а каждая сохраняется отдельно со
своим заголовком — чтобы разбивку можно было собрать позже, не
перезагружая файл.

## Сверка (этап 3, здесь только правило)

Перед сохранением прогона отчёт на экран:

- смен, простоев, минут, записей выпуска — из файла и из разбора;
- суммы формовки, упаковки и брака по месяцам — из файла и из базы;
- список непрочитанного с листом и строкой;
- расхождение с прошлым прогоном: стало больше или меньше и на
  сколько.

Сохранение — после того, как человек это увидел.

## Чего в схеме нет намеренно

- Толкования 14 спорных колонок. Они лягут в узкую таблицу как есть, с
  заголовком из файла, и получат имя после ответов.
- Правки файла из системы. Отчёт ведут в Excel, система его читает.
- Автоматической чистки старых прогонов.
