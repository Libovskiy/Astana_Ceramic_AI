# ACAI — защита критических данных

Добавлен безопасный поток удаления критических данных.

## Что изменено

- База знаний больше не удаляется прямым `DELETE` из интерфейса.
- Сотрудник создаёт запрос на удаление.
- Запись БЗ получает `pending_delete` и перестаёт использоваться приложением/ИИ, но физически остаётся в SQLite.
- Владелец системы видит очередь запросов в `Настройки → Защита`.
- `Отклонить` возвращает БЗ в `active` — это rollback без восстановления из backup.
- `Подтвердить окончательное удаление` перед физическим удалением автоматически создаёт копию SQLite в `backups/`.
- Журнал действий не имеет операции удаления.
- Старые прямые DELETE endpoints для БЗ/инструкций больше не выполняют физическое удаление.
- Добавлена таблица `protected_delete_requests`; миграция выполняется автоматически при старте.

## Важное ограничение текущей версии

В этой версии финальное подтверждённое удаление физически подключено для:

- `knowledge`
- `procedures`

Для остальных критических объектов очередь можно расширить тем же механизмом, но их физическое удаление специально не подключено, чтобы не уничтожить связанные исторические данные случайно.

## Владельцы

Владельцы задаются через `.env`:

`OWNERS=alibek`

Это отдельный список логинов, а не роль. Роль администратора сама по себе не даёт права окончательного удаления.

## AI-запросы

Обычные вопросы к AI не вызывают `log_action` в добавленном механизме защиты. Если AI когда-нибудь будет выполнять критическую операцию (например, удаление), сама операция всё равно должна проходить через этот же поток подтверждения.
