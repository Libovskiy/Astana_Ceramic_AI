# ACAI WebHMI Collector — расширение Chrome

Собирает показания с панели WebHMI массаподготовки и отправляет их на
сервер ACAI. Без него на главной и в аналитике нет данных с датчиков.

## Как работает

Расширение встраивается во вкладку панели `http://192.168.1.74/lp` и
раз в секунду читает регистры, которые панель и так показывает.
Вход в панель — по сессии того, кто её открыл; пароль расширение не
хранит и не использует.

Куда уходят данные:

| что | куда | как часто |
|---|---|---|
| все показания | `/api/sensors/live` — в память сервера, для экрана | раз в секунду |
| загрузки, авария, моточасы | `/api/sensors/push` — в базу `monitoring.db` | раз в 30 секунд |
| частоты приводов (Гц) | `/api/sensors/push` — в базу | раз в 7 минут |

Список регистров — `ALL_REGISTERS` в `content.js`.

**Сбор идёт только пока открыта вкладка WebHMI.** Закрыли вкладку —
данные перестают приходить. На странице «Настройки → WebHMI коллектор»
видно, когда пришло последнее показание.

## Установка

1. Откройте `content.js` и впишите в `SENSOR_KEY` значение
   `SENSOR_PUSH_KEY` из файла `.env` на сервере. В репозитории вместо
   ключа заглушка — это намеренно: с ключом любой в заводской сети
   сможет писать в историю датчиков, а по ней считаются простои.
   **Не коммитьте файл с настоящим ключом.**
2. Chrome → `chrome://extensions` → включите «Режим разработчика».
3. «Загрузить распакованное расширение» → выберите эту папку.
4. Откройте в Chrome вкладку `http://192.168.1.74/lp` и войдите в панель.

Если сервер ACAI не на этой же машине, замените `localhost:8000` в
`content.js` (`ACAI_LIVE`, `ACAI_PUSH`) и в `manifest.json`
(`host_permissions`) на его адрес.

## Если данные не приходят

- Вкладка WebHMI закрыта или вышли из панели — откройте и войдите.
- Сервер отвечает 403 на `/api/sensors/push` — ключ в `content.js` не
  совпадает с `SENSOR_PUSH_KEY` в `.env`.
- Ошибки видно в консоли вкладки WebHMI: строки с пометкой `[ACAI]`.
